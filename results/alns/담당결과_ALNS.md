# 다차량 실험 담당 결과 · ALNS

담당자 hyunseungjoon · 담당 알고리즘 ALNS · 실행 2026-11-23 · macOS-26.5.1-arm64-arm-64bit · Python 3.11.7

## 구현과 실행

LA DLA7 거점의 2018-08-03 배송 기록을 사용했다. 차량 6대의 배송지 923곳을 대상으로 차량 배정과 방문 순서를 평가했다. 원자료의 동일 경로 및 거점 이동시간을 사용하고, 서로 다른 원래 경로 사이의 이동시간은 좌표 거리로 추정한다. 저장소의 솔버와 데이터 파일 해시는 SA 실행 기록과 일치한다. [데이터 준비와 한계](https://github.com/Johyeonwoooooooo/algorithm_5team/blob/e6c77dcfc0ec1b46a363017569fc52aa2906d55a/docs/DATASET_CHANGES.md)

기존 `solvers_multi.py`의 `alns()`, `_destroy()`, `_repair()`, `_insertions()`를 확인했다. 한 번에 배송지 2~8곳을 제거한다. 제거 전략은 무작위, 우회 비용, 인접 배송지 중에서 고르고, 삽입 전략은 마감 우선 또는 regret-2로 고른다. regret-2는 최선의 위치를 놓쳤을 때 비용 증가가 큰 배송지부터 넣는다. 이후 후보의 성과에 따라 제거·삽입 전략의 선택 가중치를 조정한다. [ALNS 코드](https://github.com/Johyeonwoooooooo/algorithm_5team/blob/e6c77dcfc0ec1b46a363017569fc52aa2906d55a/solvers_multi.py#L458)

- 시나리오 B는 기록된 차량을 고정한다. C는 탐욕법이 새로 배정한 해에서 시작한다. C2는 B와 같은 탐욕 초기해에서 시작하고 재배정을 허용한다.
- B·C·C2 각각 80,000회, 시드 11·29·47·61·83으로 총 15건을 실행했다.
- 가중치는 대기 1, 지각 초당 5, 지각 배송지당 600이다. 차량마다 출발부터 마지막 배송 완료까지 29,639.2초 이내로 제한하고, 용량과 배송지별 1회 방문을 검사한다.

다음 명령은 저장소 루트에서 Python 3.11.7로 실행한다.

```sh
python3.11 check_multi.py
python3.11 run_multi.py --algo alns --alns-iterations 80000 --seeds 11 29 47 61 83 --jobs 10 --output ../python3117_run
python3.11 check_multi.py --results ../python3117_run
```

## 실제 데이터에서 관찰한 동작

C2 시드 11의 1번째 반복을 같은 반복 설정으로 별도 추적했다. 우회 비용을 기준으로 8곳을 뺀 뒤 regret-2로 재삽입했다. DN V1→V2, OZ V5→V3로 담당 차량이 바뀌었고, 후보 비용은 73,797.2 → 73,395.1로 낮아져 채택됐다. 두 경로의 비용과 제약은 별도 채점기로 확인했다.

## 해석과 확인

- 전 구간을 추정 이동시간으로 바꿔 이미 찾은 해를 다시 채점하면, C2의 이동시간은 줄었으나 지각 벌점이 반영된 비용은 증가했다. 재배정 효과는 이동시간 추정에 민감하며, 이번 표본은 특정 날짜의 여섯 경로다.
- C2 이동시간은 시드별로 1,005.5~1,023.5분이었다. 저장소의 4만 회 결과와 이번 8만 회 결과의 C2 평균 비용은 61,250 → 60,866였다. 8만 회 결과의 최적성은 검증 범위 밖이다.
- 독립 검산은 기록 경로 A와 재실행한 ALNS 15건에서 누락·중복, 용량, 근무시간 상한, 비용과 재채점 값을 확인했다.
- 15건의 차량 배정·방문 순서, 차량별 지표, 재배정 내역, 수렴 기록이 기존 결과와 일치했다. `runs.csv`는 `runtime_seconds`만, `settings.json`은 `python`과 `platform`만 달랐다.
